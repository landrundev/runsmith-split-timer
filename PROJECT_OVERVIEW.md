# Runsmith Split Timer — Project Overview

**App Name:** Runsmith Split Timer
**Bundle ID:** `com.runsmith.splitdeck`
**Platform:** iOS 16.0+
**Language:** Swift 5.9 / SwiftUI
**Persistence:** Core Data
**Build Tool:** XcodeGen (`project.yml`)
**Version:** 1.0 (Build 1)

---

## Purpose

A live race-timing app for track & field coaches and meet directors. Supports individual events (800m, 1600m, 3200m, custom) and relay events (4×400m, 4×800m, 4×1600m, 4×3200m). The coach taps a single button to mark splits as athletes cross, then assigns them to athletes via card taps. Results are viewable immediately and exportable as CSV.

---

## Key Features

| Feature | Description |
|---|---|
| **Meet management** | Create meets, add multiple races, view history |
| **Quick Race** | Start a race without a meet; history browsable from home |
| **Live Timing** | Real-time clock (CADisplayLink, 30fps), MARK SPLIT + card-tap assignment |
| **Relay timing** | 4-leg relay with ordered athlete assignment, leg times computed by subtraction |
| **Auto-assign** | Single-athlete race: MARK SPLIT auto-assigns without a card tap |
| **Undo** | Full undo stack; restores unassigned marks from consumed timestamps |
| **Resume** | App-kill recovery via `RaceStateCache` (JSON blob with debounced write) |
| **Results** | Ranked table (Cumulative or Lap Times), relay leg breakdown, total time |
| **CSV Export** | Shares a dated CSV file via iOS share sheet |
| **Haptics** | Heavy (mark), Medium (assign), Rigid (undo) |

---

## Architecture

MVVM with a domain layer. All business logic lives in pure/static functions (`RaceDomain`) or the `@MainActor` engine (`TimingEngine`). Views are thin.

```
View  →  ViewModel  →  TimingEngine / RaceDomain  →  SplitDeckStore (Core Data)
                                                   →  RaceStateCache (JSON)
```

No third-party dependencies.

## Data Model

### Core Data Entities

| Entity | Key Fields |
|---|---|
| `AthleteEntity` | id (UUID), name, teamName?, colorHex, notes? |
| `MeetEntity` | id (UUID), name, date, location? |
| `RaceEntity` | id (UUID), meetId?, name, eventType (Int16), distanceMeters (Int32), trackLengthMeters (Int32), splitsPerLap (Int16), athleteIdsData (Binary/JSON), startedAt?, endedAt?, status (Int16) |
| `SplitEntity` | id (UUID), raceId (UUID), athleteId (UUID), lapIndex (Int32), elapsedMs (Int64) |

### Key Model Rules
- `laps` and `expectedSplitsPerAthlete` on `Race` are always **computed**, never stored
- `startedAt` stored as UTC; never converted for calculations — only for display
- `splitsPerLap` is always 1 for MVP but all logic parameterises off it
- `athleteIds` array on `Race` defines **display order** for individuals and **leg order** for relays
- For relay races: `distanceMeters = trackLengthMeters = legDistanceMeters` → `laps = 1` per athlete

## Timing Engine

`TimingEngine` is the core of live timing:

- **Clock:** `CADisplayLink` on `.common` run loop (works during scroll), capped to 20–30 fps
- **Elapsed time:** Always recomputed as `Date() - startedAt`. Never accumulated.
- **Mark flow:**
  1. Tap MARK SPLIT → `handleMarkTap()` → timestamps the moment, appends to `unassignedMarks[]` (sorted by timestamp), adds to undo stack
  2. Tap athlete card → `handleCardTap(athleteId:)` → pops oldest unassigned mark (FIFO), creates a `Split`, saves via `onSaveSplit` closure
  3. If no unassigned marks exist, `handleCardTap` timestamps live (used by relay leg recording)
- **Undo:** Reverses last action — either removes a mark or deletes a split and re-inserts its mark
- **Cache:** After every state change, stages a `RaceStateBlob` (JSON) with 750ms debounce. On app background, `flushImmediately()` is called synchronously.
- **Resume:** On relaunch, if a blob exists for the current race ID, user is prompted to resume or start fresh

## Race Flows

### Individual Race
1. Home → Quick Race (or Meet → Add Race) → Race Setup
2. Select event type (800m / 1600m / 3200m / Custom), name, athletes
3. Live Timing: tap MARK SPLIT for each lap crossing, tap athlete cards to assign
4. When all athletes complete their final lap, END RACE button appears
5. Finish → Results screen → Export CSV or Done

### Relay Race
1. Race Setup: switch to Relay tab, pick 4×400 / 4×800 / 4×1600 / 4×3200
2. Assign 4 athletes in leg order (tap to add/remove)
3. Live Timing: "RECORD LEG N" button records current athlete's split using live timestamp
4. After all 4 legs recorded, FINISH RELAY appears
5. Results: leg time (computed by subtraction from previous cumulative) + cumulative column

### Single-Athlete Shortcut
When exactly 1 athlete is in the race, MARK SPLIT auto-assigns to that athlete — no card tap needed.

## Results & Export

`RaceDomain` provides all display and export logic through a shared `CellValue` path — display and CSV never diverge.

**Time format:** `M:SS.cc` (minutes, seconds, centiseconds)
**CSV filename:** `YYYY-MM-DD_[MeetName|QuickRace]_[EventName]_race-[shortId].csv`
**Columns (individual):** Athlete, Place, then one column per lap (cumulative or lap time depending on display mode)
**Columns (relay):** Leg, Athlete, Leg Time, Cumulative Time

## Building

### Prerequisites
- Xcode 15+
- XcodeGen: `brew install xcodegen`

### Generate & Open
```bash
cd "Runsmith Split Timer"
xcodegen generate
open RunsmithSplitTimer.xcodeproj
```

### Archive for App Store
1. Set your Apple Developer Team in `project.yml` → `DEVELOPMENT_TEAM`
2. Re-run `xcodegen generate`
3. In Xcode: select **Any iOS Device** → **Product → Archive**
4. Distribute via App Store Connect

## Known Design Decisions

- No network calls — fully offline
- Core Data chosen over SwiftData for iOS 16 compatibility
- `TimingEngine` uses injected closures (`onSaveSplit`, `onDeleteSplit`, `onStageCache`) so it has zero direct dependency on Core Data or the file system — fully testable in isolation
- Relay leg times computed by subtraction at display/export time, not stored — only cumulative `elapsedMs` is persisted
- `isIdleTimerDisabled = true` during live race to prevent screen sleep
